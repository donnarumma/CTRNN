# Continual Program Benchmark v1 — delivered results

Full run completed at the 2026-09-29/30 session boundary under Octave 11.1.0.
Code and operational protocol: [CTRNN benchmark](/media/Data/OneDrive/tools/CTRNN/continual_program_benchmark/README.md).
English methods: [continual_program_benchmark.tex](/media/Data/OneDrive/theory/ActiveAndDeep-theory/Virtuality/continual_program_benchmark.tex).

The run contains 60 frozen six-block learning streams, 360 acquisitions per
condition, and 10080 per-stream/stage/task/condition rows. Motor costs pool
24 MPB evaluation layouts and 12 geometry-transfer layouts. Test cue outcomes
are integrated exactly; training samples are frozen noisy streams. No population
confidence intervals or independent-episode interpretation is attached.

- `summary.csv/json`: final-stage outcomes and validation metadata.
- `retention.csv`: all individual test results, with acquisition/evaluation stages.
- `queries.csv`: acquisition expenditure and learned-code metrics per block.
- `acquisition.csv`: every question prefix, including the prior.
- `learning_streams.csv`: readable environment mapping/curriculum, evaluator only.
- `cpb_report.mat`: full numerical report, archived checkpoints, fixture and SPM check.
- `protocol.json`: explicit finite experimental assumptions.
- `cpb_summary_rows.tex`, `cpb_metrics.tex`: generated LaTeX values.
- `cpb_continual_results.pdf/png`: overview, generated by `cpb_plot_results.m`.
- `cpb_acquisition_results.pdf/png`: equal-budget prefixes, generated by `cpb_plot_acquisition.m`.
- `sha256_manifest.json`: delivered code/fixture/result hashes, paths relative to the CTRNN benchmark folder.

Active acquisition learns 99.17% of codes with 4.19 queries on average; yoked
random acquisition learns 87.78% at that expenditure. The strictly equal
four-question prefixes give 91.94% versus 88.61%, and both conditions reach
99.72% at twelve questions. Ordinary active completion is 69.47% against a
70% cue ceiling; providing the correct memory slot gives 99.17%. Thus code
acquisition and noisy retrieval must be reported separately. Archived codes
and cue counts remain exactly unchanged; the compiled and dictionary controls
match interpreter behavior.

To regenerate from the saved report, add the code folder, load `report`, then
call `cpb_write_results`, `cpb_plot_results`, and `cpb_plot_acquisition` with a
chosen output directory. The source README documents full reruns and the
independent original-SPM12 reference. Teacher/model information and oracle
conditions are declared explicitly; this is not a multi-agent experiment.
